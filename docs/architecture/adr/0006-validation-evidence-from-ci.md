# ADR-0006: Validation evidence generated from the test suite in CI

- Status: Accepted
- Date: 2026-10-14

## Context

Computer software assurance (FDA CSA, GAMP 5 2nd edition) favours
risk-based, automated testing and accepts records generated by tools over
hand-written test scripts. Traceability from requirements to tests is still
expected.

## Decision

- User requirements live in `docs/validation/urs.yaml`.
- Tests declare the requirements they verify with
  `@pytest.mark.urs("URS-nnn")` (function, class or module level).
- `python -m gxp_agent_runtime.validation` parses test files (no import),
  reads the JUnit results of the same run, and writes a package with the
  matrix, per-test outcomes, summary, commit and a sha256 digest. `--strict`
  fails unless every requirement is traced and verified and no test cites an
  unknown requirement.
- CI runs it on every push; releases attach the package, JUnit XML and the
  Markdown matrix to the GitHub release.

## Consequences

- OQ evidence for a deployed version is the release's validation package
  plus the image provenance attestation; PQ remains site-specific.
- A requirement without a passing test blocks the release.
